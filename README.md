# Petra — موقع الرعاية والخدمات

نسخة تشغيلية **محلية 0.14.0** مبنية من الصفر بـNext.js/NestJS وPostgreSQL/Redis. تشمل الهوية والرعاية وتجارة العيادة والمحاسبة الاختبارية والباقات والإقامة والتجميل والمكتبة المراجعة والمجتمع والإنقاذ والنقل والإدارة. لم تكتمل كل تفاصيل الخطة أو مرحلة الإطلاق الإنتاجي؛ الحالة الدقيقة في [KNOWN_ISSUES](KNOWN_ISSUES.md) و[PROGRESS](PROGRESS.md).

## التشغيل

المتطلبات: Node 24، pnpm 11.25.0، Docker Compose، FFmpeg وFFprobe. من `/workspace/pet`:

```bash
bash scripts/install-cloud.sh
```

يثبت بـfrozen lockfile ويجهز `.env` ويحافظ على السر الموجود، ويشغل PostgreSQL/Redis/Mailpit ويطبق migrations وseed وفحوص المشروع والبناء. seed لا ينشئ حسابات دخول أو يمنح أدوارًا. شغّل في ثلاث طرفيات:

```bash
pnpm dev:api
pnpm dev:web
pnpm dev:worker
```

API على 4000 والويب 3000 وفحص العامل 4002. أعد تشغيل API بعد تعديل الشفرة؛ الويب يدعم HMR. بعد استعادة بيئة لا تفترض بقاء العمليات أو Docker volumes. APP_ORIGIN يطابق origin الويب، وAPI_BASE_URL وجهة داخلية للـBFF؛ الافتراضي loopback. لا تضع --env-file في NODE_OPTIONS. إذا احتاج pnpm مسارات كتابة:

```bash
export XDG_DATA_HOME=/workspace/.cache/data
export XDG_CACHE_HOME=/workspace/.cache/cache
export XDG_STATE_HOME=/workspace/.cache/state
export npm_config_cache=/workspace/.cache/npm
export NEXT_TELEMETRY_DISABLED=1
```

### رحلة عيادة وطلب اختباري

أنشئ حساب المراجع والجهات وأكّد البريد من Mailpit على 8025. اعتمد العيادة والطبيب/السائق من حساب مراجع مخول بجلسة MFA. أنشئ فرعًا وخدمة للموعد، ومنتجًا وموردًا وطلب شراء للاستلام. استلم البضاعة ثم طابق الفاتورة؛ المخزون يأتي من الخادم وليس حقل رصيد في المتصفح. العميل يحجز checkout ثم يجري تحصيلًا **اختباريًا**؛ العيادة تجهز وتشحن وتسلم. المرتجع يثبت الاستلام والحالة ويعكس المال/العمولة/تكلفة FIFO حسب الكمية.

الحجز الطبي لا يفتح السجل وحده؛ يلزم تفويض المالك للطبيب والعيادة. الأصل الموقع لا يعدل؛ التصحيح إضافة. استعمال باقة يحتاج زيارة موقعة مطابقة. التبرعات أموال مقيدة وليست إيراد المنصة، والرحلة المطلوبة لا تسجل ربحًا قبل الإكمال.

### مراجع وصلاحيات مالية محلية

لا مدير افتراضي. بعد حساب موثق وتفعيل TOTP، ينفذ operator مخول:

```bash
PETRA_ALLOW_LOCAL_ADMIN_BOOTSTRAP=true pnpm admin:bootstrap reviewer@example.test
```

تلغى الجلسات ويلزم دخول جديد بخطوتين. التفويض المالي مستقل، لحسابين مختلفين، باستخدام `scripts/grant-local-finance.mjs` كما في [دليل التشغيل](docs/OPERATIONS_RUNBOOK.md). لا تنفذ أي منحة ضمن startup أو seed. الأدوات ترفض الإنتاج. محاسب العيادة يُعد القيد/الصرف، ومعتمد آخر يراجعه؛ الإدارة العامة لا تمنح الصرف ضمنيًا.

## البيانات والمالية والوسائط

البيانات محفوظة في PostgreSQL. الأموال bigint/BigInt ووحدات IQD صحيحة (1000 وحدة صغرى = 1 د.ع)، ولا سعر أو رصيد موثوق من React. الدفتر منفصل لكل عيادة والمنصة، والقيود المرحّلة متوازنة وغير قابلة للتعديل في DB. العمليات المالية الحالية sandbox وتُرفض خارج APP_ENV=local؛ لا PSP/webhook أو مصرف حقيقي أو تبرعات فعلية.

الصور حتى 5 MB يعاد ترميزها WebP مع إزالة metadata؛ MP4 حتى 20 MB/60 ثانية لا ينشر قبل تحويل العامل. الملفات خاصة في `.data/media` وتتحقق صلاحياتها عند كل طلب؛ الطبية لا تتحول إلى روابط static عامة. التشفير والتخزين والفحص الإنتاجي تحتاج مزودًا وسياسات إطلاق.

عامل Redis يعالج أحداث outbox بإعادة محاولة محدودة وdead letters، وينشئ إشعارات داخل التطبيق ويحرر حجوزات المخزون المنتهية ويعالج الفيديو. توقفه لا يلغي المعاملات الناجحة. الإشعارات ليست بريدًا/SMS/push. راجع runbook للتشغيل والمراقبة والنسخ والاسترجاع.

## متغيرات البيئة

الأسماء في `.env.example`، والسر يولده `pnpm env:prepare` مرة واحدة في ملف 0600 غير متعقب. لا تطبع `.env` أو dumps.

- DATABASE_URL، REDIS_URL: خدمات التطبيق.
- APP_ENV=local، APP_ORIGIN، API_BASE_URL: بيئة محلية وحدود origin والـBFF.
- BETTER_AUTH_SECRET: سر توقيع/تشفير مستقل، لا قيمة ثابتة في المصدر.
- MAIL_MODE وSMTP_HOST/PORT/FROM: Mailpit محليًا؛ الإنتاج يحتاج HTTPS وSMTP موثقًا مع TLS.
- PETRA_MEDIA_ROOT: مجلد خاص؛ الافتراضي `/workspace/pet/.data/media`.
- WORKER_HEALTH_PORT: الافتراضي 4002، يستمع loopback.
- PETRA_DEMO_MODE: أمثلة `/demo` الموسومة، منفصلة عن بيانات الحسابات والمعاملات.

## الفحوص

```bash
pnpm check
pnpm db:migrate
pnpm db:seed
pnpm test:db
pnpm build
pnpm security:built
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium pnpm test:e2e
pnpm backup:verify
pnpm audit --audit-level high
```

runner ينشئ قاعدة petra_e2e وسرًا ومجلد وسائط مؤقتًا، ويطبق migrations، ويشغل API/الويب على 4100/4101 و3100/3200 وعاملًا على 4102، ثم يحذف قاعدة ومجلد اختباره فقط. يحتاج Mailpit/Redis/PostgreSQL وDocker وFFmpeg/FFprobe. fixtures المهنية والـMFA لا تعمل إلا على قاعدة اختبار معزولة؛ لا تخفف محددات معدل HTTP. على جهاز بلا Chromium نظامي ثبّت متصفح Playwright الرسمي واترك متغير مساره غير محدد.

الصور وقياسات الحمل المحلي في `docs/evidence`؛ traces والتقارير الحساسة غير متعقبة. التقرير التاريخي للمرحلة 02 في `docs/PHASE02_REPORT.md`. المعمارية في ADR 000–003، وحالة كل متطلب في REQUIREMENTS_TRACEABILITY، وحدود الإطلاق في KNOWN_ISSUES.

## حماية الأسرار والتحقق الأمني

`.env` خاص بالخادم بصلاحية 0600 وخارج public وGit والحزمة. `pnpm security:check` يفحص المصدر والفهرس وpublic، و`pnpm security:built` يفحص أيضًا أصول المتصفح بعد البناء. hook قبل commit وCI يشغلان الفحوص؛ لا تضع أسرارًا في NEXT_PUBLIC أو إعداد env في Next. التفاصيل في [مراجعة الأمان](docs/SECURITY_REVIEW.md).

الاعتماد المالي للقيود/الموردين والمرتجعات والصرف يتطلب MFA ودخولًا خلال 30 دقيقة، بالإضافة للصلاحيات وفصل الأشخاص. بعد ترحيل 0014 سجل الدخول من جديد. API_HOST افتراضيًا loopback؛ لا تعرض PG/Redis/Mailpit للإنترنت. الإنتاج يتطلب HTTPS وPostgreSQL verify-full وRedis TLS موثقًا وSMTP TLS، ويرفض demo والمالية/التخزين المحلي.

لإنشاء حزمة مصدر بعد الفحوص: `pnpm release:source`؛ ترفض الكتابة فوق أرشيف سابق وتولد SHA256 بجانبه. يمكن تمرير مسار جديد خارج المستودع كوسيط. تبقى حسابات ومفاتيح التشغيل منفصلة عنها.

## استكمال الرعاية والتبني والحملات في 0.11.0

- `/care/directory`: ملف طبيب معلن ومعتمد داخليًا، بحث وتقييم زيارة مكتملة وحجز من الأوقات المتاحة.
- `/doctor/planning`: ملف الدليل، دوام أسبوعي بتوقيت بغداد وتوليد أوقات وإجازات.
- `/clinic/:id/calendar`: استقبال وحضور/غياب، غرف علاج وإغلاقات، دون فتح الملاحظات الطبية.
- `/care/calendar`: مواعيد ومتابعات شهرية بصلاحيات المالك والوصاية، وتذكيرات داخل التطبيق مع تأجيل DND.
- `/care/pets/:id/passport`: لقاحات ووصفات وزيارات موقعة مع إضافاتها؛ طباعة/حفظ PDF خاص بالمالك.
- `/safety/:token`: بطاقة سلامة اختيارية عامة محدودة، مستقلة عن الملف الطبي. إنشاؤها وإلغاؤها من ملف الحيوان، وصلاحيتها بحد أقصى سنة.
- `/adoption` و`/admin/operations`: تعديل إعلان وإعادة مراجعته وإغلاقه، وتعديل حملة قبل التبرعات وإيقاف استقبال الجديد مع حفظ التاريخ.

طبق migrations حتى 0019 ثم أعد API والعامل. تحتاج التذكيرات المؤجلة والعرض المحدّث للـQR والعامل إلى البناء الجديد. التفاصيل في [ADR 005](docs/adr/005-care-scheduling-and-safety.md).

## كتالوج المتجر في 0.12.0

خيارات مرتبطة بمنتج أصلي، كل منها SKU وسعر ومخزون مستقل، مع فئات وعلامات وباركود ووحدة ومواصفات وعمر ملائم وصور مرتبة. عدّلها داخل تجارة العيادة، ثم افتح تفاصيل المنتج لاختيار SKU وإضافته للسلة. فلاتر السوق تشمل النوع والفئة والعلامة والعيادة والمدينة والسعر والتوفر.

إعدادات `clinic/:id/storefront` تحفظ الاسم والنبذة والمدينة والتوفر وسياسات التسليم والإرجاع والشعار والغلاف. صور المتجر والمنتجات تتطلب موافقة نشر وصورة خاصة يملكها الموظف وغير طبية. إخفاء المتجر يمنع الطلبات الجديدة وصوره المنشورة دون محو سجل الطلبات. تفاصيل المنتج والمتجر تتطلب حساباً موثقاً حالياً؛ SEO عام ومزود شحن فعلي غير مفعّلين.

طبّق حتى 0021 وأعد API والعامل. القرارات في [ADR 006](docs/adr/006-catalog-and-published-media.md)، والحدود المتبقية في KNOWN_ISSUES.

## العمليات المكتملة في 0.13.0

- `clinic/:id/inventory`: مستودعات وفروع ودفعات وصلاحية وحجر ونقل وإتلاف باعتماد مالي مستقل، واستلام جزئي موثق لا يتجاوز PO؛ السعر والمتاح من الخادم، ولا شحن للمنتهي.
- `clinic/:id/finance/statements`: تقارير مؤرخة للدخل والمركز المالي وأعمار مستحقات الموردين، مع سداد جزئي ورفض/سحب طلب موافقة دون أثر مالي.
- `marketplace`: دفتر عناوين خاص، snapshot عنوان الطلب، وتتبع يدوي من لوحة العيادة وسجل تجهيز/شحن/تسليم immutable. لا اتصال ضمني بمزود شحن.
- `social`: بحث يحترم الخصوصية والحظر، مشاهدات قصة للمالك، قصص مميزة اختيارية حتى سنة، روابط مشاركة داخلية وتحديث المحادثة المفتوحة كل أربع ثوان.
- `adoption`: اقتراحات lost/found لصاحب البلاغ بحسب المدينة والنوع، دون كشف الموقع الخاص أو ادعاء إثبات ملكية.
- `taxi`: حجز مجدول ومتعدد الحيوانات مع سعة وأنواع المركبة والراكب المصاحب، وإعادة فحص حق الحجز عند قبول السائق، وإلغاء الطلب المجدول الفائت عبر العامل.

طبّق migrations حتى 0027، وأعد API والعامل والويب. ADR 007–010 توثق الحدود. لا تعديل لملف env الخاص أو منح حسابات تلقائياً.

## استكمال 0.14.0

- داخل `/clinic/:id/promotions`: كوبونات ثابتة/نسبية بحد وفترة وسقف وحد لكل عميل، رمز واحد للعيادة دون تكديس. شروط محفوظة وتعطيل بversion، والحجز المنتهي/الملغى يحرر الاستخدام، بينما التحصيل والمرتجع يحتفظان به. إعداد ضريبة حصري افتراضيه صفر، محلي فقط وبصلاحية مالية وMFA؛ ليس نسبة قانونية معتمدة.
- السوق يعاين مجموع المنتجات والخصم والضريبة لكل عيادة من الخادم قبل الحجز. اللقطة محمية، والتبدل يوجب معاينة جديدة. أكبر البواقي وBigInt ورد كمية تراكمي يحفظان كل وحدة صغرى، والضريبة التزام مستقل والعمولة على الصافي دونها.
- `/grooming` و`/clinic/:id/grooming`: خدمة وفرع وأنواع وإضافات سعر/مدة، موظف وغرفة ومواعيد وإخفاء بالإصدار؛ سعة الحيوان والموظف والغرفة مشتركة مع المواعيد الطبية بقيد DB. حجز وتحصيل مؤجل وإتمام وإلغاء ورد وتقييم وإيصال تشغيلي مطبوع. صور إتمام خاصة بموافقة تسحب، مع منع نشر الملف نفسه في المجتمع أو المتجر.
- `/care/library` و`/clinic/:id/library`: نسخ نصية ثابتة، مراجع HTTPS، مراجعة طبيب مستقل موثق قبل النشر، إخفاء بعد تعديل أو سحب الاعتماد أو مرور سنة. بحث حسب النص والنوع والعمر، طلب تصحيح خاص ورد محفوظ لا يعدل المقال تلقائياً. لا محتوى طبي منشور آلياً أو تشخيص فردي.

الترحيلات 0028–0030 إضافية؛ قرارات ADR 011–013. تحفظ إعدادات البيئة الحالية وأسرارها ولا تضيف حسابات افتراضية أو تكامل دفع خارجي. راجع PROGRESS لنتائج الاختبارات النهائية وKNOWN_ISSUES لبقية نطاق الخطة.
