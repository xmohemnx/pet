# تحسين تجربة Petra المشتركة — 2026-10-23

طلب المالك: «طور ui/ux باستخدام السكلات الي طلبت منك تثبتهم». هذه دفعة تحسين للمسارات المشتركة ضمن هوية Petra الحالية؛ لا تغيير لمعمارية الموقع أو قواعد المال والطب والصلاحيات. مصدر الواجهات المثبت `41851243224fbc66907cca32d5510f138e9f975e` على `codex/ui-ux-20261023`، فوق فرع أنواع الحسابات السابق.

## ما تغير

- تنقل الهاتف أصبح قائمة جانبية بـdialog أصلي: تركيز محمي ودوران Tab، Escape، إغلاق من الخلفية، عودة التركيز، منع تمرير الصفحة وراء القائمة، واستعادة التمرير عند الإغلاق أو الانتقال للحاسوب. التنقل المكتبي يبقى شريطاً عادياً.
- بحث في أسماء الأقسام المصرح بها، مع معالجة حالة عدم وجود نتائج؛ ليس بحثاً في بيانات المرضى أو المتجر. شريط الهاتف السريع يصل لمساحة النوع الحالي والرعاية والمجتمع والحساب، مع منطقة الأمان السفلية.
- توحيد أزرار العمل والحقول وحالات التركيز بألوان teal الحالية، تكبير حقول الهاتف إلى16px وأهداف اللمس، ضبط عناوين الأقسام وإيقاع المسافات. بيانات السياق في العناوين المشتركة تظهر بعد العنوان، وأزرار الطبيب متباعدة وتلتف على الهاتف.
- حقل كلمة مرور مشترك بتسمية واضحة وإظهار/إخفاء لا يرسل النموذج ولا يمحو القيمة؛ استُخدم للدخول والتسجيل والاستعادة والأمان والحذف. لا منع للصق أو تعطيل لمدير كلمات المرور. فشل إعادة إرسال التأكيد لا يعرض نجاحاً كاذباً، وخطأ الإرسال يركز رسالة التعافي.
- تنبيه اتصال موحد في الحساب والمجتمع والهوية وصفحات التعافي، وتحسين مسار404 وروابط الرجوع. لا ادعاء بالحفظ أثناء انقطاع الاتصال.
- إصلاح عائق أول استخدام للمجتمع: `GET social/profile` كان يرسل جسماً فارغاً عندما لا يملك الحساب ملفاً اجتماعياً، فيفشل JSON وتظهر صفحة خطأ. أصبح يرجع JSON `null` فعلياً، مع تحقق من الحساب الجديد ودخول واجهة المجتمع. لا ملفات اجتماعية أو نشاط مُختلق لملء الصفحة.

التسجيل يبقى بأربعة أنواع ثابتة، وتغيير النوع يحتاج طلباً وقرار الإدارة؛ اختيار المهنة لا يمنح اعتماداً. حذف الحساب يبقي السجلات المقيدة المعلنة. لم تتغير قواعد الوصول أو اعتماد المال.

## المهارات والأدلة

- Impeccable: تحسين وتكييف وتقوية المسارات، العقد [المثبت](../../apps/web/.impeccable/surfaces/apps-web-components-identity-shell-tsx.md)، ومراجعة مستقلة ثم توثيق النظام.
- Taste: مبادئ شاشات العمل، هدوء الأسطح وحقيقة البيانات وكثافة المهمة، مع الحفاظ على الاتجاه القائم؛ لا سحب هوية جديدة ولا صور جديدة.
- Web Design Guidelines: نُسخت الإرشادات الحالية من مستودع Vercel الرسمي للمراجعة المحلية، مع تطبيق قواعد لوحة المفاتيح والنماذج واللمس والتعافي.
- React Best Practices وComposition Patterns: مكونات قابلة لإعادة الاستخدام، أحداث اتصال بتنظيف listeners، قراءة حقل البريد عبرref، واستبقاء جلب البيانات المتوازي في الصفحات.
- `pnpm skills:check`: نجحت21مهارة/441ملفاً/105فحوص صياغة؛ Impeccable0.1.16 وVercel65.2.0. لا مصادقة Vercel أو نشر مطلوبان.

الفاحص الآلي نُفّذ مرة واحدة على خمسة أهداف مشتركة: صفر ملاحظات أساسية و10إشارات استشارية لحجوم خطوط/لون تحذير وتوثيقها. محاولة الصياغة الأولى باستخدام `--target` رُفضت قبل الفحص؛ استُخدمت صياغة الملفات الصحيحة دون إعادة فحص لاحقة. [النتيجة](UI_UX_MECHANICAL_FINDINGS.json) ليست اعتماد جودة بصرياً.

## الحدود

التجربة والفحوص داخل Chromium مع أحجام320/390/768/1440 وRTL وaxe، مع محاكاة لمس عبرCDP وتقليل الحركة. لا فحص فعلي على جهاز iOS/Android أو اعتماد متصفحات آخر، ولا ادعاء تدقيق أمان مستقل أو جاهزية كل المنصة. المحتوى الفارغ في الخدمات والمتجر والرعاية يعكس قاعدة اختبار جديدة؛ لا حشو بأرقام أو مستخدمين حقيقيين. الصور المفهومية السابقة باقية دون تعديل.

لا نشر عام أو تطبيق هجرة علىSupabase أو تفعيل خدمة مدفوعة أو دمج إلىmain. تبقى دفعات السوشل وأنواع الحسابات السابقة محفوظة، وتبقى صورها أدلة تاريخية مستقلة.
