# تهيئة الفيديوهات القديمة لـHLS

بعد بناء API، يعاين المشغل فيديوهات `ready` غير الطبية التي لا مشتقات لها:

```sh
pnpm --filter @petra/api build
pnpm media:backfill-hls --dry-run --limit=10
pnpm media:backfill-hls --apply --limit=10
```

الوضع الافتراضي معاينة فقط، والحد الأقصى 100 فيديو لكل تشغيل. كرر المعاينة والتنفيذ على دفعات بعد فحص العدادات. تعمل الأداة بإعدادات قاعدة البيانات والتخزين الخاصة الموجودة؛ لا تضع أسراراً في معاملات الطرفية أو المحادثة. لا تُشغلها عبر حسابات زوار الموقع.

المخرجات: `candidates/completed/skipped/failed/dryRun`. يعيد أي فشل رمز خروج 1؛ أصلح المصدر أو المزود ثم أعد المحاولة. العنصر المقفول بتشغيل آخر يُتخطى، والفيديو الذي اكتملت مشتقاته لا يعاد توليده. لا تغيّر الأداة ملف MP4 أو ملكيته أو حالته أو صلاحيات قراءته. الملفات الطبية مستثناة؛ لا توسّعها يدوياً لتجاوز سياسة الوصول.

يلزم FFmpeg وffprobe والمساحة الخاصة نفسها المستخدمة بالعامل. يدعم المسار التخزين المحلي وS3 المشفر؛ يحتاج S3 فاحص ClamAV متاحاً وحديثاً. تظل الملفات المولدة خاصة، وكل قائمة وقطعة تتطلب إذن قراءة الفيديو الحالي. لا تفعّل هذه العملية رفع الإنتاج أو مزود دفع أو نشر الموقع.

صورة API تتضمن `scripts/backfill-hls.mjs` أيضاً؛ يمكن للمشغل استعمالها ببيئة محقونة خاصة دون ملف `.env`، وبمساحة staging خاصة قابلة للكتابة كما يحتاج عامل الوسائط. لا تستبدل ذلك بإتاحة الملفات للعامة.
