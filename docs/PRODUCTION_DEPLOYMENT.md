# تشغيل إنتاجي مجاني قابل للاستضافة الذاتية

هذه حزمة تجهيز، وليست إثبات جاهزية Petra للإطلاق. أُنشئت قاعدة PostgreSQL على Supabase وفق [دليل الربط](SUPABASE_DEPLOYMENT.md)، وخدمة مهام Render مجانية، لكن لا خادم تطبيق منشور أو بريد خارجي مربوط أو حسابات دفع أو تحقق تراخيص. طلب التجربة المستضافة المجانية وعوائقه في [دليل الحالة الحالي](FREE_HOSTING_STATUS.md). الاختبارات المحلية لا تعتمد العراق ضريبياً أو طبياً، ولا تحل محل مراجعة أمنية مستقلة. راجع `PRODUCTION_PLAN.md` ونتيجة `pnpm production:check` قبل أي إطلاق.

## الصور والعزل

`infra/production/Dockerfile` ينتج صوراً منفصلة للويب وAPI والعامل. الويب يستخدم Next standalone ولا يحمل ملف البيئة أو كلمة مرور PostgreSQL أو مفتاح الجلسات. مراحل التشغيل تعمل كمستخدم 1000 دون root. سياق Docker يستبعد ملفات البيئة والمفاتيح والنسخ الاحتياطية وبيانات المستخدم وGit والاختبارات. تثبيت الاعتمادات من lockfile ثابت، وصورة Node الأساسية مثبتة ببصمة.

Compose يربط API والعامل بشبكة داخلية دون نشر منافذهما للمضيف. Caddy ينهي TLS ويوجه WebSocket إلى API، وبقية الطلبات إلى واجهة الويب. ملفات النظام للقراءة فقط، وصلاحيات Linux مسقطة، ومجلدات مؤقتة محدودة. معالجة الوسائط داخل `/tmp/petra-media`؛ التخزين الدائم يكون S3 الخاص، وليس هذه المساحة المؤقتة. اربط مجلد وصلة ClamAV الخاص عبر `PETRA_SCANNER_SOCKET_DIR` وحدد `PETRA_SCANNER_GID` لمجموعة الوصلة؛ يتحول مسارها داخل API والعامل إلى `/run/petra-scanner/clamd.sock` بصلاحية ربط للقراءة فقط. يجب أن تسمح صلاحيات المجلد والوصلة بوصول هذه المجموعة.

خدمات PostgreSQL وRedis والبريد والتخزين والفحص ليست خدمات إنتاج مهيأة ضمن هذه الحزمة؛ استعمل خدمات مخصصة موثوقة أو استضفها مع TLS ونسخ مشفرة وسياسات وصول. البريد المجاني يظل بحاجة إلى نطاق وسمعة وإعداد SPF/DKIM/DMARC صحيح.

يدعم البريد أيضاً `MAIL_MODE=resend` عبر HTTPS، مع `RESEND_API_KEY` و`MAIL_FROM` على الخادم؛ لا تلزم إعدادات SMTP في هذا الخيار. لا حساب مزود مربوط حالياً. مرسل `resend.dev` التجريبي لا يكفي لإرسال عام ولا يجتاز بوابة تهيئة بريد الإطلاق. راجع ADR031؛ دعم HTTPS مفيد على استضافة تحجب SMTP لكنه لا يثبت ملاءمة بقية هذه الحزمة لها.

الاستضافة المطلوبة لهذا المسار خادم Linux يدعم Docker Compose وعمليات مستمرة ووصلة فحص خاصة. الاستضافة المشتركة التي تشغل ملفات PHP فقط لا تكفي لهذه البنية. حدد المزود ونوع الخادم وموارده قبل اختيار عناوين الخدمات وطرق النسخ والمراقبة.

## إعداد المشغل

1. على خادم تملكه، جهز نطاقاً وDNS وDocker Compose. المنافذ العامة الوحيدة اللازمة للويب 80/443؛ قواعد البيانات والتخزين والفحص لا تعرض للعامة.
2. ضع أسرار الإنتاج خارج checkout في ملف خاص بصلاحية 0600 ومالك خدمة التشغيل. لا ترسل المفاتيح في المحادثة، ولا تضعها ضمن `NEXT_PUBLIC_*` أو build args أو Git. يحتوي الملف على `APP_ENV=production`، و`PETRA_DEMO_MODE=false`، و`APP_ORIGIN` HTTPS الفعلي، وسر جلسة عشوائي مستقل بطول 48 حرفاً على الأقل، وPostgreSQL بـ`sslmode=verify-full` وRedis بـ`rediss` وكلمات مرور مستقلة، وSMTP مصادق مشفر. `OSRM_ENDPOINT` وجهة خدمة طرق معتمدة للمشغل؛ الاستضافة الذاتية خيار مجاني، وتشغيلها وتحديث بياناتها يحتاجان موارد.
3. جهز دور migration منفصلاً عن دور التشغيل داخل قاعدة الإنتاج نفسها. دور التشغيل لا يملك الجداول، ولا يملك SUPERUSER أو BYPASSRLS أو CREATEROLE أو CREATEDB أو إنشاء عناصر schema. لا تنسخ مستخدم قاعدة التطوير إلى الإنتاج. ضع `MIGRATION_DATABASE_URL` في ملف صيانة منفصل عن ملف API/العامل، ومرره لخدمة migrate عند الصيانة فقط.
4. مرر `RELEASE_COMMIT` لبصمة Git الكاملة للنسخة المراجعة، و`PETRA_DOMAIN` للنطاق، و`ACME_EMAIL` لبريد الشهادات و`PETRA_PRODUCTION_ENV_FILE` لمسار الملف الخاص، ومجلد وصلة الفاحص ومجموعتها. هذه إعدادات للمشغل؛ لا تستخدم `docker compose config` أو `inspect` دون ترشيح لأن المخرجات قد تحتوي القيم السرية. قوالب الأسماء فقط في `docs/examples/`؛ قيم الأسرار فيها فارغة عمداً.

```bash
PETRA_IMAGE_TAG="$RELEASE_COMMIT" pnpm containers:build
```

يدعم أمر البناء شهادة وكيل البيئة عبر `CODEX_PROXY_CERT` إن كانت مهيأة، كـBuildKit secret مؤقت؛ لا تنسخ الشهادة إلى الصورة ولا تعطل فحص TLS. يعمل البناء المعتاد دونها على خادم لا يحتاج شهادة وكيل خاصة.

## تحقق الصور قبل ربط الخادم

```bash
pnpm containers:build
pnpm test:containers
```

هذه الأوامر تبني صور `local-verify` وتختبر API والعامل وNext standalone مع قاعدة وRedis مؤقتين ودون seed. لا تستخدم قاعدة التطوير أو الإنتاج. المنافذ المنشورة للاختبار loopback فقط، والحاويات تعمل بمستخدم 1000 ونظام ملفات للقراءة فقط. يتأكد التحقق من صحة الخدمات والأصول ومنع المسارات الخاصة وبقاء بوابة الإنتاج مغلقة. ينظف موارده المؤقتة وملف أسراره بعد التشغيل. يتطلب مقبس Docker المحلي في Linux؛ لا يثبت هذا تحقق TLS أو البريد أو أدوار قاعدة الإنتاج أو صلاحية خادم المالك.

يمكن إعادة التحقق من صور commit محدد بـ`PETRA_IMAGE_TAG="$RELEASE_COMMIT" pnpm test:containers`. لا تنسب نتيجة اختبار الصور إلى خادم لم تختبره.

## الترحيل على الخادم

خذ نسخة احتياطية مشفرة واختبر استرجاعها خارج الإنتاج أولاً. لتطبيق الترحيلات، مرر **مسار ملف الصيانة** إلى `PETRA_PRODUCTION_ENV_FILE` في جلسة صيانة خاصة، ثم:

```bash
docker compose -f infra/production/compose.yml --profile maintenance run --rm migrate
```

هذا المسار يفرض اتصال TLS متحققاً ودور migration مختلفاً، ويفحص بصمات الترحيلات داخل معاملة واحدة وقفل. لا seed، ولا حسابات fixture، ولا مدير تلقائي في الإنتاج. أعد المتغير إلى **ملف التشغيل الذي لا يحتوي بيانات دور migration** بعد انتهاء الصيانة. تعيين الصلاحيات بعد الترحيل مسؤولية المشغل وفق تقرير مراجعة الأدوار.

## بوابة الإطلاق

```bash
pnpm production:check
```

لملف إعدادات إنتاج خارج checkout، استخدم `node --env-file=/path/to/private-runtime.env scripts/production-check.mjs` بدلاً من تعديل ملف التطوير. أبقِ ملفات الأدلة الخاصة متاحة لأمر الفحص وفق مساراتها الفعلية.

الأمر يخرج رموز فحوص فقط وحالة blocked ما دامت الميزات والإعدادات والأدلة ناقصة. لا يعد اتصال PostgreSQL/Redis في `/ready` تصريحاً بالنشر؛ `/ready` فحص تشغيلي للعملية. تقرير المراجعة الأمنية المستقلة يجب أن يحدد commit النسخة، والجهة المراجعة، والنطاقات، ووقت الإصدار والانتهاء، وتوقيع Ed25519 من مفتاح عام موثوق حصل عليه المشغل من المراجع خارج قناة التقرير نفسها. لا تولد اعتماداً لنفسك لتجاوز الفحص. مسارات الملفات الخاصة: `SECURITY_REVIEW_REPORT` و`SECURITY_REVIEW_PUBLIC_KEY_FILE` و`RETENTION_POLICY_FILE`.

لا تشغل edge علناً قبل إغلاق البنود المتبقية واعتماد المراجعة. بعد ذلك فقط:

```bash
docker compose -f infra/production/compose.yml up -d --wait web api worker edge
```

تحقق من TLS وCookie وCSRF وCSP وWebSocket عبر النطاق الفعلي، ومن أن `/.env` و`/.git/config` وملفات النسخ غير قابلة للقراءة، ومن خصوصية الوسائط والصلاحيات عبر المستخدمين والعيادات. قِس الأداء وحمل WebSocket وتكاليف المزود على بيئة مماثلة للإنتاج؛ قياسات بيئة التطوير ليست سعة إنتاج.

## التراجع والنسخ

احتفظ بصورة النسخة السابقة وبنسخة قاعدة ووسائط متسقة ومشفرة ومختبرة. الترحيلات المطبقة ثابتة؛ لا تعدل checksum ولا تشغل DOWN مرتجلاً. قبل ترقية schema، تحقق أن الإصدار السابق يستطيع قراءته، وإلا استخدم استرجاعاً مخططاً مع توقف كتابة ومنع تكرار webhooks ومراجعة آثار الأموال. النسخ وسياسة الاحتفاظ والحجز القانوني تتطلب اعتماداً فعلياً. لا تحذف سجلات طبية أو مالية بمجرد تخمين مدة قانونية.
