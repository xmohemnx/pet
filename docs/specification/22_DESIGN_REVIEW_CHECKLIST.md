# 22 — قائمة قبول التصميم والحركة لـ Petra

## المبدأ
**تصميم متحرك احترافي، لا واجهة قالب إداري مكرر**. كل حركة تحسن إدراك المستخدم للمعلومة والتفاعل؛ لا تُضحي بالسرعة أو الأمان أو الوضوح. افحص `12_DESIGN_MOTION_SYSTEM.md` قبل التنفيذ.

## مراجعة عامة لكل شاشة
- [ ] شخصية Petra واضحة: هوية ألوان Teal/Orange متوازنة، طباعة عربية فخمة، بصريات حيوانات مناسبة وليست مكررة.
- [ ] RTL أصلي: عناوين، مسارات، أيقونات اتجاهية، حقول إدخال، جداول، حركات سحب، وأزرار رجوع؛ الأرقام والعملة بتنسيق bidi سليم.
- [ ] responsive عملي على 320، 375/390، 768، 1024، 1440 بكسل؛ لا قص أو تراكب أو تمرير أفقي غير مبرر.
- [ ] الشاشات العامة عالية الجودة: Hero متحرك مدروس، reveal بتتابع، صور/رسوم جذابة، CTA واضح، عمق بصري وتنقّل سلس.
- [ ] الداشبوردات دقيقة: أولوية للوظائف، وفلاتر واضحة وتبويبات وحالات تحميل وفارغ وخطأ، لا تُستبدل البيانات بعدادات وهمية.
- [ ] كل زر ومدخل ومودال يرتبط بسلوك حقيقي مع نجاح/فشل واضح؛ لا روابط ميتة.
- [ ] المكوّنات تحتوي على حالات hover / focus / pressed / disabled / loading / error / success مع أنيميشن متزن.
- [ ] لا تُخفى التحذيرات المالية أو أخطاء المرضى داخل حركات أو توست عابر.
- [ ] نوافذ تأكيد للعمليات الخطرة، وسجل من نفذها وأين.
- [ ] دعم `prefers-reduced-motion` بشكل محترم، بدون parallax أو scroll-jacking، ومحتوى قابل للاستخدام حتى لو تعطلت مكتبة الحركة.
- [ ] Lazy-loading للميديا والخرائط والمخططات، تجنب الفيديو التلقائي بالصوت، وتحسين أداء الأجهزة المتوسطة.
- [ ] قابلية استخدام لوحة المفاتيح وfocus visible وlabels وaria للمكوّنات التفاعلية.
- [ ] مقاييس LCP/INP/CLS تقاس على بيئة اختبار ببيانات شبه واقعية؛ لا ادعاءات 60fps دون قياس.
- [ ] تدفقات موبايل سليمة للمس والانتقالات والانقطاع وضعف الشبكة.

## عناصر يجب عرضها للموافقة قبل تعميمها
1. **Landing Desktop**: Hero غني بصرياً، أقسام خدمات تفاعلية، خطوات الرعاية، واجهة منتج، قسم إنقاذ، CTA.
2. **Landing Mobile**: نسخة مستقلة محسنة للأداء وsafe areas واتجاه RTL.
3. **Customer Care Dashboard**: بطاقة حيوان حيّة، تقويم، لقاحات وتنبيهات، الانتقالات بين الحيوانات.
4. **Clinic Commerce + Finance**: جدول منتجات قابل للفرز والبحث، حركة إضافة/تعديل، لوحة أرباح مبنية على أمثلة fixture واضحة.
5. **Doctor Dashboard**: مواعيد وتدفق السجل الطبي، تأكيدات واضحة قبل توقيع ملاحظة طبية.
6. **Driver Dashboard**: حالة اتصال، طلب رحلة حقيقي/تجريبي موسوم، توقيت وحالة مسار واضحة.
7. **Admin Dashboard**: مراجعة تراخيص/بلاغات ومعاملات عالية الخطورة مع audit.
8. **Social Reels**: انتقال رأسي سلس وإيقاف الفيديو غير المرئي مع احترام تفضيلات الحركة والبيانات.

## حالات الفيديو والتواصل
- عدم تشغيل صوت تلقائي.
- التمرير لا يشغّل أكثر من الفيديو الضروري المرئي في وقت واحد.
- skeleton يحافظ على مكان الفيديو ويمنع CLS.
- الإعجاب والمتابعة والتعليق والرسائل لا تعتمد على animation بدل التأكيد من API.
- فشل الشبكة له إعادة محاولة آمنة دون إنشاء منشور أو دفع مكرر.

## مخرجات مرحلة التصميم
- Storyboard بواجهات الرئيسية والعملاء والعيادة + tokens وأشكال motion محددة.
- screenshots للنسخ responsive والـ reduced motion.
- قائمة المخالفات المصنفة P0/P1/P2 قبل تعميم التصميم.
- فحص مسارات RTL وkeyboard وتفاعل touch في E2E؛ ليس فقط تقييم جمال التصميم.
