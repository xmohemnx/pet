# ADR 028 — تجهيز حاويات النشر واختبارها محلياً

الحالة: تجهيز للنشر بطلب المالك بتاريخ 2026-10-22؛ بيانات النطاق والاستضافة لم تُقدّم بعد.

## القرار

نبقي صور الويب وAPI والعامل منفصلة ومبنية من lockfile ثابت. تجمع مرحلة البناء ملفات التشغيل والترحيل والصيانة داخل مجلدَي API وNext standalone، ثم تنسخ كل مجموعة مرة واحدة إلى صورتها. يقلل ذلك طبقات النسخ المكررة أثناء البناء، خصوصاً مع Docker VFS في البيئة السحابية. وصلة شهادة وكيل البناء اختيارية ومؤقتة عبر BuildKit secret، ولا تنتقل إلى صورة التشغيل. يستخدم API دعم وكيل Node المدمج مع التحقق من TLS.

تظل جذور الحاويات للقراءة فقط والمستخدم 1000 بلا capabilities. تضبط مساحة معالجة الوسائط على `/tmp/petra-media`؛ التخزين الدائم خاص وخارجي. يربط API والعامل مجلد وصلة ClamAV للقراءة فقط، مع مجموعة الوصلة المحددة من المشغل. الويب لا يأخذ ملف أسرار API.

يُبنى الاختبار المحلي بأسماء `local-verify`، أو ببصمة commit يحددها المشغل. ينشئ فحص الصور قاعدة وRedis خاصين به، ويطبق المخطط دون seed، ثم يتحقق من الصحة والأصول ومنع الوصول المجهول ومسارات الأسرار والعرض التجريبي. اتصالات الاختبار المحلية لا تعادل TLS أو أدوار قاعدة الإنتاج. لا ينشر الفحص منفذاً عاماً أو Caddy أو حسابات دخول، ويزيل حاوياته وشبكته وملف الإعدادات المؤقت الخاص به فقط.

لا يفتح نجاح اختبار الصورة بوابة الإنتاج. تبقى الاستضافة والنطاق والشهادات والبريد والخدمات الخاصة ومزودو الأعمال وسياسة الاحتفاظ والمراجعة المستقلة متطلبات فعلية قبل الإطلاق. إعدادات المالك تدخل عبر ملفات خاصة خارج Git، مع فصل بيانات migration عن بيانات التشغيل.

## حدود الدليل

أوامر إعادة التحقق ودليل المشغل في `docs/PRODUCTION_DEPLOYMENT.md`. لا تنسب نتيجة اختبار صور محلية إلى خادم لم يُربط أو يُختبر بعد.
