# 032 — موجز اجتماعي مستقل ووسائط مرتبة

الحالة: تنفيذ شريحة قبول أولى، 2026-10-23. لا تغيير لمعمارية Next/Nest/PostgreSQL.

المشكلة: SocialCenter يجمع مهاماً متعددة، والنشر يقبل وسيطاً واحداً. إنشاء ألبوم على الواجهة وحدها يتجاوز سياسة السماح بالميديا الحالية أو يترك وسائطه الإضافية غير قابلة للعرض.

القرار: توسيع SocialProfile بمعرف فريد وavatar اختياري؛ إضافة social_post_media مرتبة مع ترحيل المرفق الحالي دون حذفه؛ إبقاء asset_id كأول وسيط للتوافق؛ إضافة timeline بمؤشر مركب من وقت الإنشاء الدقيق والمعرف. تظل social/feed تعيد array للعملاء السابقين. إضافة creation_key وفحص تطابق الحمولة لإعادة المحاولة دون منشور مكرر. كل وسيط اجتماعي يجب أن يكون ملك المرسل وجاهزاً وغير مرتبط بحيوان أو محادثة. media.authorize يراجع ظهور منشور الألبوم أو صلاحية avatar، مع الحفاظ على قواعد الطب والعيادة.

التجربة: Feed وCreate وProfile منفصلة، وواجهة الإدارة السابقة على /social/settings. شاشات viewer وinbox الأولية تعيد استخدام الخدمات القائمة مع إعلان حدودها. لا ترتيب AI أو badge أو مدفوعات جديدة. بيانات القبول في قاعدة E2E المحلية فقط.

الهجرة0046 توسّع حماية صور إتمام التجميل إلى كل وسيط ألبوم وإلى avatar، وتمنع إعادة تصنيف وسيط اجتماعي/صورة شخصية كصورة خدمة خاصة في الاتجاه العكسي. حراس قاعدة البيانات يتحققون كذلك من المالك وجاهزية الملف وعدم الارتباط بالطب أو chat؛ يقفل API مجموعة أصول الألبوم بترتيب معرفاتها قبل الربط. بذلك لا تعتمد الحماية على إخفاء خيار في الواجهة.

مخاطر واختبارات: تغيّر سياسة الوسائط يجب أن يثبت A/B/حظر/حساب خاص، ويُمنع الربط بمرفق طبي أو chat. تساوي created_at لا يسقط منشورات. تعديل handle لا يغيّر ملكية المحتوى، وتعارض handle يعيد409. يبقى النقاش المتداخل وExplore المتقدم وتاريخ الرسائل غير المحدود من بنود المراحل التالية، لا من اكتمال هذه الشريحة.
