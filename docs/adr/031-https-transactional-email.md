# ADR 031 — البريد عبر HTTPS للتجربة المستضافة

طلب المالك تجربة الوظائف عبر الإنترنت بخطط مجانية فقط، وأكد أنه لا يملك خدمة بريد. مراجعة [حدود Render](https://render.com/docs/free) في 2026-10-23 أثبتت حجب منافذ SMTP المعتادة 25/465/587 عن Web Service المجانية. تغيير علم المعاينة لا يحل هذا القيد.

نضيف موصل Resend اختياريًا عبر HTTPS على وجهة ثابتة، دون SDK أو تبعية جديدة. `MAIL_MODE=resend` يحتاج `RESEND_API_KEY` و`MAIL_FROM` على الخادم فقط. يبقى SMTP الحالي للتطوير والاستضافة التي تدعمه. اختيار غير معروف أو إعداد ناقص يفشل مغلقًا، ولا رجوع إلى بريد محلي أو تعطيل تأكيد البريد. لا تغيير في الهوية أو الجلسات أو الصلاحيات أو شروط الخدمات المالية والوسائط.

مهلة الطلب عشر ثوان، وتحويلات HTTP مرفوضة، ولا إعادة محاولة تلقائية أو طباعة مفتاح/مستلم/رابط تأكيد/استجابة مزود. مفتاح idempotency مشتق من الرسالة لتقليل إرسال الرسالة نفسها مرتين عند إعادة الطلب خلال نافذة المزود. قبول API للرسالة ليس دليل تسليم إلى صندوق الوارد.

وفق [حصص Resend](https://resend.com/docs/knowledge-base/account-quotas-and-limits)، الخطة المجانية محدودة. المرسل التجريبي `onboarding@resend.dev` مخصص لتجربة بريد صاحب حساب Resend؛ إرسال عام يحتاج نطاق إرسال موثق. لا ننشئ حساب مزود باسم المالك أو نطلب مفاتيح في المحادثة. إضافة الموصل لا تربط حسابًا ولا ترسل بريدًا حقيقيًا ولا تثبت تشغيل الموقع.

فحص الإنتاج يقبل تهيئة SMTP الحالية أو إعداد Resend بمرسل مخصص؛ المرسل التجريبي لا يمر كإعداد إطلاق عام. تظل بقية بوابات الإنتاج مستقلة. توثق العوائق والخدمات الفعلية في `docs/FREE_HOSTING_STATUS.md`.
