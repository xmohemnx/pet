# 022 — نزاعات النقل والتعويض الاختباري

يفتح العميل أو السائق المرتبط نزاعاً واحداً بعد اكتمال الرحلة أو إلغائها، ويضيف الطرفان إفادات ثابتة، مع منع الوصول للغريب. البلاغ أثناء الرحلة يبقى متاحاً بمسار الحوادث الحالي. لا تضبط هذه النسخة مهلة قانونية لتقديم المطالبة دون سياسة معتمدة.

المراجعة لا تمنح للإدارة العامة تلقائياً. تحتاج capability مستقلة `manage_transport_disputes` وجلسة MFA صالحة. اقتراح التسوية يحتاج تفويض finance maker، واعتمادها يحتاج finance checker مختلفاً وجلسة حديثة خلال 30 دقيقة. القرار والإفادات محفوظة وثابتة، مع تدقيق الوصول والانتقالات دون وضع نص القضية أو موقع الرحلة في السجلات التشغيلية.

التسويات المتاحة اختبارياً: عدم تعويض، أو رد كامل لتحصيل رحلة مكتملة. لا خصم عند إلغاء رحلة لم تحصل. الرد يسجل عكس القيد الأصلي مرة واحدة، ويخفض مستحق السائق والعمولة ويخفض التحصيل الاختباري. يتحقق من كفاية المستحق ورصيد التحصيل تحت القفل المالي نفسه المستخدم للصرف، ثم يحفظ القرار والقيد داخل معاملة واحدة. فحص مؤجل في قاعدة البيانات يربط القيد بالرحلة والمعد والمعتمد ومبالغ الأصل. رفض المقترح يغلق النزاع دون أثر مالي. لا يوجد رد مصرفي فعلي ولا اعتماد لشروط النقل العراقية.

تفويض reviewer المحلي متاح فقط بأداة المشغل المحلية وبعلم `--transport-disputes` الصريح؛ لا واجهة أو تسجيل ذاتي يمنحه. منح الإنتاج يحتاج إجراء إدارة صلاحيات معتمداً خارج bootstrap المحلي. دعم التعويض الجزئي وتحصيل ذمم تعويض سبق صرفها والتصعيد القانوني يحتاج سياسة إضافية ومزود أموال؛ لا يجري إنشاء رصيد سلبي أو ادعاء دفع ناجح بدونهما.
