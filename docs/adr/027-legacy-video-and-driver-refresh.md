# ADR 027 — تهيئة فيديو قديم وتحديث عروض السائق

الحالة: مقبول ضمن استكمال النواقص المحلية بتاريخ 2026-10-22.

## القرار

تقرأ مساحة السائق `driver/home` الموثق تلقائياً كل خمس ثوانٍ بعد انتهاء الطلب السابق، أثناء ظهور الصفحة فقط. العودة للشبكة أو إظهار الصفحة يعيدان القراءة. الطلب له مهلة عشر ثوانٍ ويلغى عند الإخفاء أو مغادرة المسار؛ لا طلبات متراكبة. أخطاء 401/403/404 تمحو مساحة السائق المعروضة وتوقف المحاولات. تختفي أزرار العروض المنتهية بالساعة المحلية حتى أثناء انقطاع الشبكة؛ القبول النهائي ووقت الانتهاء وصلاحيات السائق يظل تحققها على الخادم. هذا polling، وليس دفع WebSocket أو تتبع موقع بالخلفية.

تعمل `media:backfill-hls` من الطرفية فقط ولا تُضاف إلى API أو العامل التلقائي. المعاينة هي الوضع الافتراضي، والتنفيذ بـ`--apply`، وحد الدفعة من 1 إلى 100. يعاد فحص أهلية الفيديو الجاهز غير الطبي الذي لا مشتقات له تحت قفل `FOR UPDATE SKIP LOCKED`. تُقرأ نسخة MP4 من مسار القراءة الخاص نفسه بحد 64MiB، ويعاد فحص S3 عبر ClamAV؛ ثم يُفحص زمن لا يتجاوز دقيقة وتُولد مشتقات HLS القائمة داخل معاملة واحدة. المصدر والأسماء والملكية وحالة الفيديو لا تتغير.

ينظف الفشل مشتقات المحاولة ومساحتها المؤقتة، ويترك الفيديو قابلاً لإعادة المحاولة والتشغيل الأصلي. نجاح بعض العناصر لا يخفي فشل غيرها: تعيد الأداة عدادات فقط ورمز خروج 1 عند أي فشل. لا أسرار أو مفاتيح كائنات أو تفاصيل طبية في مخرجاتها. تبقى مصالحة الكائنات اليتيمة بعد انهيار مفاجئ وحدود الاحتفاظ والتشغيل الإنتاجي مسائل مستقلة.

## التحقق

اختبارات dispatch للظهور التلقائي والانتهاء دون شبكة وسحب الاعتماد وaxe والهاتف؛ واختبارات media-backfill للمعاينة والتوازي والتكرار وعزل الطبي والمحادثة وفشل المصدر والروابط الرمزية وإصلاح المصدر وإعادة المحاولة. يضيف تحقق المزود المحلي سيناريو S3 مشفر مع تعطل الفاحص واستعادة الخدمة وحفظ MP4.
