# ADR 002 — الرعاية والموافقة وحجز الوقت

الحالة: تنفيذ محلي، 2026-10-21. يبنى على ADR 001 ومتطلبات 03 و16 و17.

- الحيوان له مالك أساسي؛ الأوصياء منح منفصلة قابلة للإلغاء: profile وmedical وbooking. مشاركة الصلاحيات والموافقة العلاجية للمالك وحده. لا حذف مادي لسجل طبي؛ الأرشفة تمنع الحجز الجديد.
- الطبيب المعتمد يحتاج انتسابًا وعضوية doctor_member في عيادة معتمدة، وموعدًا مسندًا إليه، وموافقة المالك المحددة للطبيب والعيادة وغير المنتهية. صلاحية clinic_admin أو platform_admin لا تمنح قراءة طبية. كل قراءة طبية تسجل IDs فقط في audit.
- موافقات القراءة/الكتابة تفحص في الطلب نفسه. معاملات الحيوان تقفل صفه لتسلسل الإلغاء والتعديل. لا وصول طوارئ استثنائي قبل سياسة معتمدة.
- أوقات صريحة UTC، عرض Asia/Baghdad؛ خدمات بفترة دقائق ثابتة، دون حساب تشخيص/جرعات أو جدول لقاح آلي. لا دفع أو إثبات إيراد من الحجز.
- PostgreSQL يقفل الموعد ويمنع تداخل حجز الطبيب والحيوان بـ exclusion constraints. مفتاح UUID لكل محاولة يحفظ الاستجابة نفسها إن تطابق الحيوان والموعد، ويرفض إعادة استخدامه لمحتوى مختلف.
- الزيارة مسودة بإصدار، ثم توقيع الطبيب ينهي الموعد ويضيف المهام المختارة صراحة ضمن المعاملة نفسها. trigger يمنع تغيير/حذف الأصل الموقع؛ الإضافة اللاحقة سجل مستقل غير قابل للتعديل. الوصفة واللقاح وطلب/نتيجة الفحص بيانات منظمة يكتبها الطبيب ضمن النسخة الموقعة.
- تنبيهات هذه الشريحة قائمة مهام محفوظة في التطبيق وoutbox؛ التسليم الخارجي وإعادة المحاولة خلفيًا مؤجلان. الملفات الخاصة، نقل الملكية، QR عام، تكرار الدوام/الإجازات/الغرف وPDF معتمد تحتاج شرائح لاحقة؛ لا واجهات توحي بتوفرها.

طلب الفحص داخل نص الزيارة الموقع يبقى كما هو. migration 0006 يفصل medical_lab_orders لاعتماد النتيجة بعد الزيارة بواسطة الطبيب المعالج فقط؛ انتقال requested→reviewed مرة واحدة يثبت الفاعل والوقت والنص. trigger يمنع تعديل النتيجة المعتمدة أو حذف/تغيير أصل الطلب؛ التصحيح إضافة موقعة للسجل. لا رابط ملف عام أو مصدر مختبر خارجي مفترض.
