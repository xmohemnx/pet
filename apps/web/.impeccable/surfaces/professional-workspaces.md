## Direction contract

The question comes before configuration. Teal, locally bundled IBM Plex Sans Arabic, the existing navigation shell, flat surfaces and explicit native controls remain fixed. The task structure changes substantially; this is not a claim that the previous shared CSS polish completed these screens.

- Customer `/app` and `/care`: “What does my companion need next?” Lead with actual pet profiles and a useful create-first-pet action; doctor availability and service destinations follow. Account settings stay at `/account`. No invented appointment or patient data.
- Doctor `/doctor`: “Which visits need me?” Today/upcoming/all filters derive from the actual assigned visits. Show the visit time, animal, clinic, attendance state and existing authorized visit actions. Independent work tools and publish-time form sit alongside the queue. Empty today must permit viewing genuine future appointments.
- Clinic `/clinic/:id`: “Where does my team work today?” Authorized calendar summary first, clinic context beside it, capability-filtered department directory next. Progressive native disclosure houses existing branch, invitation, membership and service administration. Calendar load failure is distinct from an empty schedule. Never request the calendar for finance-only staff.
- Driver `/driver`: “What ride am I doing, and what can I accept?” Active rides precede offers/requests. Current/history controls use real ride states. Vehicle readiness is visible, configuration opens deliberately, and the server ledger remains explicitly a test balance. No fake GPS map, distance, nearest-driver or earnings claim.
